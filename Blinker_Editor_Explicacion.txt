=====================================================================
 1. QUE ES Y COMO ARRANCA
=====================================================================
Un editor de codigo tipo Sublime Text / VS Code escrito en Python con tkinter.
No usa librerias externas: solo Python 3 con tkinter (en Linux: sudo apt install python3-tk).

    python main.py

Tiene: pestanas, arbol de carpetas, resaltado de sintaxis, autocompletado,
errores en vivo con servidores LSP, Build/Run con panel de salida, paleta de
comandos (Ctrl+Shift+P), temas, paquetes instalables desde GitHub y
recuperacion de archivos sin guardar si el programa se cierra mal.

Regla de diseno que sigue todo el proyecto: main.py es la ventana (usa tkinter);
casi todo lo demas son modulos "puros" SIN tkinter, y por eso se pueden
probar o reutilizar solos (highlight, build, packages, themes, libs, lsp,
suggest, recovery). Los que SI usan tkinter: main, ui, icons, suggest_ui.

 highlight.py  (432 lineas)
---------------------------------------------------------------------
Convierte texto en rangos de color. NO usa tkinter. Piezas:

---------------------------------------------------------------------
 suggest.py  (339 lineas)
---------------------------------------------------------------------
Autocompletado "sin servidor": keywords, funciones integradas, snippets y las
palabras que ya estan en tu archivo. Es sensible al contexto (context()): no
sugiere dentro de comentarios ni strings, ni despues de ".", "->", "::", ni
cuando estas nombrando algo (def, class, fn...). Orden de prioridad: z1 keywords,
z2 integradas, z3 snippets, z4 palabras del archivo.

---------------------------------------------------------------------
 suggest_ui.py  (286 lineas)
---------------------------------------------------------------------
El popup de sugerencias (dibujado en un Canvas): iconos por tipo, letras
coincidentes resaltadas, detalle y pie de ayuda; escala con el zoom.
Los iconos se leen de icons/suggest/<nombre>.png (si falta uno dibuja uno de color).

---------------------------------------------------------------------
 lsp.py  (448 lineas)
---------------------------------------------------------------------
Cliente del Language Server Protocol: habla JSON-RPC por stdin/stdout con un
programa externo que entiende el lenguaje. Da errores reales y autocompletado
real. Servidores que busca en el PATH (usa el primero que encuentre):
  python: pyright / basedpyright / pylsp / jedi      c/c++: clangd
  javascript y typescript: typescript-language-server  rust: rust-analyzer   go: gopls
Clases: LSPClient (un servidor) y LSPManager (uno por lenguaje/proyecto).
Todo lo que llega del servidor se procesa en poll() (el editor lo llama cada
50 ms), asi no hace falta "locks" con tkinter. Si no tienes ningun servidor
instalado, el editor sigue funcionando con suggest.py + libs.py.

=====================================================================
 5. LIBS - LIBRERIAS DE AUTOCOMPLETADO
=====================================================================
QUE SON
Un "lib" es un archivo .json que le ENSENA al editor las funciones, palabras
clave, constantes, tipos y snippets de un lenguaje o de una libreria (por
ejemplo tu BASIC, o Love2D). El editor las muestra en el popup de
autocompletado. No ejecutan nada: son solo datos. Es un "mini LSP sin servidor".

DONDE SE PONEN (dos opciones)
  A) Sueltas:   Libraries/mi_lib.json        (junto a main.py)
  B) Dentro de un paquete, y se declaran en su blinker-package.json:
         "libraries": ["libs/mi_lib.json"]
Despues:  Tools > Reload Libraries   y   Tools > Show Loaded Libraries (para ver si cargo).
Si hay un error en el .json aparece en el panel Output como [Libs] ...
IMPORTANTE: libs.py solo lee los .json de Libraries/ que esten SUELTOS ahi
(no dentro de subcarpetas); por eso borre Libraries/Love2D/ (nunca se cargaba).

CUANDO SE USA UNA LIB
Cuando el archivo abierto coincide por "languages" (id del lenguaje) o por
"extensions". Las sugerencias de la lib salen ANTES que las keywords normales.

EJEMPLO COMPLETO (probado: "OK: MiLib - 14 elementos")
Guardalo como  Libraries/mi_lib.json

{
  "name": "MiLib",
  "languages": ["basic"],
  "extensions": [".bas"],
  "comment": "'",
  "keywords":  ["If", "Then", "Else", "For", "Next"],
  "constants": ["True", "False"],
  "types":     ["Integer", "String"],
  "functions": [
    "OpenWindow(title, w, h, fullscreen, vsync) = OpenWindow(\"Hola\", 640, 480, 0, 0) # Abre una ventana",
    "CloseWindow()",
    "Cls",
    {"name": "Wait", "params": ["ms"], "doc": "Pausa en milisegundos", "insert": "Wait(1000)"}
  ],
  "snippets": [
    {"trigger": "forn", "body": "For i = 1 To $0\n\t\nNext", "detail": "Bucle For"}
  ]
}

COMO SE LEE CADA CAMPO
  name        nombre que se ve en "Show Loaded Libraries"
  languages   ids de lenguaje del editor (en minuscula). Pon este O "extensions"
  extensions  extensiones de archivo a las que aplica
  comment     prefijo de comentario para Ctrl+/ en ese lenguaje
  keywords / constants / types   listas de palabras (sin espacios)
  functions   dos formatos:
      TEXTO corto:   "Nombre(param1, param2) = texto_a_insertar # documentacion"
          - "(params)" es opcional. Sin parentesis => se inserta solo el nombre (Cls)
          - "= texto" es opcional: es lo que se escribe al aceptar. Si lo omites se
            inserta  Nombre(|)  con el cursor dentro de los parentesis
          - "# doc" es opcional: se muestra junto a la firma
      OBJETO:  {"name": "...", "params": [...], "doc": "...", "insert": "..."}
  snippets    {"trigger": lo que escribes, "body": lo que se inserta, "detail": descripcion}
              en body:  \n = salto de linea,  \t = tabulador,  $0 = donde queda el cursor

HERRAMIENTAS DE LINEA DE COMANDOS (en la carpeta del editor)
  python libs.py check Libraries/mi_lib.json       -> valida el archivo
  python libs.py from-text api.txt "RCBasic" basic .bas > rcbasic.json
      (api.txt: una funcion por linea con la sintaxis corta; las lineas que
       empiezan con ; se ignoran. Util para convertir una lista de funciones
       que copiaste de una documentacion)

SERVIDOR LSP DENTRO DE UN PAQUETE (opcional, avanzado)
Un paquete puede traer su propio servidor LSP (programa que habla JSON-RPC):
  "lsp": {"language": "basic", "extensions": [".bas"],
          "command": ["{python}", "{pkg}/server.py"]}
{python} = el Python del editor; {pkg} = carpeta del paquete.


=====================================================================
 6. PACKAGES - PAQUETES
=====================================================================
QUE SON
Un paquete es un repositorio de GitHub (o una carpeta dentro de Packages/) con
un archivo  blinker-package.json  en la raiz. Un paquete puede traer:
  - CODIGO Python ("main") que agrega comandos a la paleta, atajos, lenguajes
    de resaltado y sistemas de Build
  - TEMAS ("themes")
  - LIBRERIAS de autocompletado ("libraries")
  - un servidor LSP ("lsp")
Un repo SIN manifest tambien se instala, pero solo guarda archivos.

Diferencia con las libs:  LIB = solo datos de autocompletado (un .json).
                          PAQUETE = una carpeta completa que puede incluir libs,
                          temas y codigo que se ejecuta.

CAMPOS DEL blinker-package.json
  name, version, description, author   informativos
  main         archivo .py con register(api)   (opcional)
  libraries    lista de .json de autocompletado (rutas dentro del paquete)
  themes       lista de .json de temas
  lsp          servidor de lenguaje (ver seccion 5)

EJEMPLO 1 - paquete minimo (probado: carga y el comando funciona)
Estructura (repo de GitHub):
    hola-paquete/
      blinker-package.json
      main.py

blinker-package.json:
{
  "name": "hola-paquete",
  "version": "1.0.0",
  "description": "Mi primer paquete",
  "author": "tu-usuario",
  "main": "main.py"
}

main.py:
def register(api):
    api.add_command("Hola: Saludar", lambda: api.message("Hola desde mi paquete!"))
    api.add_shortcut("<Control-Shift-H>", lambda: api.message("Hola!"))

def unregister(api):      # opcional: se llama al desinstalar / actualizar
    pass

Despues: sube el repo a GitHub, ponle el topic  blinker-package  (para que salga
en las busquedas) y en el editor: Packages > Install Package... > escribe
usuario/repo. Veras "Hola: Saludar" en Ctrl+Shift+P.

LO QUE OFRECE EL OBJETO  api  (clase PackageAPI en packages.py)
  api.add_command("Titulo", funcion)      agrega un comando a la paleta
  api.add_shortcut("<Control-Shift-H>", funcion)   atajo de teclado
  api.editor()                            el CodeEditor de la pestana activa (o None)
  api.message("texto", error=False)       escribe en el panel Output
  api.highlight                           modulo highlight.py (register_language, make_rules...)
  api.build                               modulo build.py (register_build)
  api.app                                 la ventana principal (usala con cuidado)
  api.path                                carpeta del paquete (para leer sus archivos)
  api.name                                nombre del paquete

COMO FUNCIONA LA INSTALACION (packages.py)
  1. parse_source acepta:  usuario/repo     usuario/repo@rama
                           https://github.com/usuario/repo     .../tree/rama
  2. Descarga el .zip del repo (github.com/.../archive/HEAD.zip). Limite 100 MB.
  3. Lo descomprime en una carpeta temporal rechazando rutas peligrosas
     ("../") y zips gigantes (300 MB descomprimido).
  4. Lee el manifest, elige el nombre, lo mueve a Packages/<nombre>
  5. Lo anota en Packages/packages.json (origen, version, fecha)
  6. El editor llama a register(api) del main.py
  Buscar paquetes: usa la API de GitHub con el topic "blinker-package". Si GitHub
  te limita las peticiones, define la variable de entorno GITHUB_TOKEN.
  Upgrade = reinstala desde el mismo origen. Remove = borra la carpeta.
  OJO seguridad: un paquete ejecuta codigo Python con tus mismos permisos. El
  editor te pregunta antes de instalar; instala solo de fuentes de confianza.

 10. NUEVO: INSTALAR LIBS DESDE GITHUB (Tools > Install Library...)
=====================================================================
Tambien en la paleta (Ctrl+Shift+P): "Libraries: Install Library".

Que puedes escribir en la caja:
  usuario/repo/ruta/libreria.json            (rama por defecto)
  usuario/repo/ruta/libreria.json@rama
  https://github.com/usuario/repo/blob/rama/ruta/libreria.json   (link normal del navegador)
  https://raw.githubusercontent.com/usuario/repo/rama/ruta/libreria.json
  usuario/repo   -> se instala como PAQUETE; sirve si su blinker-package.json trae "libraries"

Que pasa: descarga el .json (max 2 MB), lo VALIDA con el mismo formato de la
seccion 5 (si esta mal lo rechaza y no guarda nada), lo guarda en Libraries/
con "source" anotado, y recarga las libs solo. Reinstalar la misma = actualizar.
Una lib es solo datos, no ejecuta codigo (por eso la confirmacion es mas simple
que la de los paquetes).

LIBS PREDETERMINADAS: main.py, lista DEFAULT_LIBRARIES (junto a DEFAULT_PACKAGES):

    DEFAULT_LIBRARIES = [
        ("usuario/repo/libs/rcbasic.json", "Autocompletado de RCBasic"),
        ("usuario/repo/libs/love2d.json@main", "Funciones de Love2D"),
    ]

Salen siempre en la lista de Install Library, con el buscador, marcadas
"(predeterminada)". Viene vacia: agrega tus repos reales (los de ejemplo no existen).
Tambien puedes empaquetar libs en un repo con blinker-package.json y
"libraries": ["libs/x.json"], y ponerlo en DEFAULT_PACKAGES.

la carga posterior y el rechazo de JSON invalido o con formato incorrecto.
